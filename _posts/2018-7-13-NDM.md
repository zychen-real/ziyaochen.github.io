### 1. 写在前面的话

这是一篇16年就挂在arXiv上面的end-end文章，是比较早关注于end-end模型的一篇文章，现在基本上实现的一些模型都与这篇文章做比较。在indroduction部分，文章种指出与端到端的闲聊型相比较，难点在于与数据库的交互。文章提出它模型的若干个个优点：是可以进行端到端的训练，但是是模块化的连接；没有直接调试用户的意图，但是每次的回复都是恰当的；有明确的与数据库交互的操作，实现较高的回复成功率；由于用户意图是展开的，可能出现模棱两可的情况。虽然使用了文本解析与权重的绑定，即减少变量，但还是需要很多数据进行训练。接下来进入模型介绍

### 2. 模型介绍

模型大体上分成四部分，intent Network(意图解析)，Belief Trackers（状态追踪槽位识别），Policy Network （认为是attention）and Database Operator（通过查找到的value替换生成的slot模板），Generation Network（生成模板）。

#### 2.1 Intent Network

Intent Network比较简单，主要有两种方法，LSTM与CNN。LSTM的公式如下：

$$z_t^N=LSTM(w_0^t,w_1^t,...w_N^t)$$

将用户的当轮话术输入LSTM，取最后时刻的隐藏层输出作为整个句子的概括，输入到policy Network。

当然我们也可以用CNN得到整个句子的表达。

### 2.3 Database

由于Belief Trackers的输出为每个slot的一个分布，我们可以根据这个分布取去数据库中进行查找符合要求的餐厅，并进行对生成的模板采用lexicalisation操作进而得到最后的自然语句。

### 2.4 Policy Network

这个做法可以很多，原文分别用普通的NN将各个模块连起来即可

$$o_t=tanh(W_{zo}z_t+W_{po}p_t+W_{xo}x_t)$$

### 2.5 Decode

Decode 部分也比较简单，baseline其实就是一个用LSTM做的language model，后来作者加入了attention，用attention model做生成。

### 3 Dataset and Parameters

文章的数据集是一个查找餐厅的任务，有680轮对话，总计1500个turns，都是人工写的。DB中有99家餐厅，可根据 口味/地点/价格（这三个叫informable slot） 查询餐厅， 选定餐厅后可查询 电话、邮编等信息。

关键参数：
采用早停与Gradient Clipping，All the hidden layer sizes were set to 50, and all the weights were randomly initialised between -0.3 and 0.3 including word embeddings. The vocabulary size is around 500。
