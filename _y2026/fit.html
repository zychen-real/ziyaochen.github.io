FIT: A Learnable Fully Interacted Two-Tower Model for Pre-Ranking System

作者：Chao Xiong, Xianwen Yu, Wei Xu, Lei Cheng, Chuan Yuan, Linjian Mo（蚂蚁集团）
发表：SIGIR 2025, July 13–18, 2025, Padua, Italy
arXiv: 2509.12948 · DOI: 10.1145/3726302.3729881
报告生成：2026-07-15 · 适用于：搜一搜 / 推荐 / 广告 预排序召回场景

摘要 / TL;DR

  • 核心问题：大规模推荐/广告系统的预排序阶段要求"毫秒级推理 + 亿级候选筛选"，传统双塔（DSSM）效率高但"晚交互"导致效果差，全交互单塔（COLD）效果好但需实时计算、扛不住十亿级候选池。
  • FIT 的答案：在双塔解耦架构中，引入两个轻量级模块，同时实现早期交互和晚期交互，且不破坏双塔的 ANN 检索效率：
    • MQM（Meta Query Module）：通过可学习的物品元矩阵 + 软/硬查询机制，在用户塔底层注入目标物品的语义先验。
    • LSS（Lightweight Similarity Scorer）：用多头子空间 + 行列式 FC替代点积，在两塔输出后做高效的晚期精细打分。
  • 关键 Trick：Soft Query（训练用，softmax 加权多个硬查询） + Hard Query（推理用，仅 1 bit 索引） + 温度参数 τ 线性衰减（1.0 → 0.001）。这样训练稳定，推理时 1 bit 索引查表即可，几乎无额外延迟。
  • 效果（4 个公开数据集）：相比 DSSM / DAT / COLD / IntTower / RankTower，AUC、Logloss、RelaImpr 三项指标全面 SOTA。
  • 效率（淘宝数据集）：训练 260s（接近双塔 250s），推理 26.9ms（与双塔 25.4ms 几乎持平），存储开销 1x（与双塔相同）。
  • 工业意义：证明"全交互 ≠ 推理慢"。FIT 是预排序阶段平衡效果与效率的 SOTA 范式，可直接借鉴到图文 / 视频号预排序场景。

2. 研究背景与动机

2.1 预排序的"两难"

大规模推荐系统的召回链路通常是：

召回（双塔 + ANN，毫秒级，亿级→千级）
  ↓
预排序（Pre-Ranking，要求毫秒级，千级→百级）
  ↓
精排（Ranking，几十~百 ms，百级→几十）
  ↓
重排（Re-Ranking，业务规则 + 多样性）

预排序的核心矛盾：

效果差（双塔）

DSSM 类纯双塔最后才内积交互，完全没利用用户-物品的细粒度特征，效果天花板低。

效率差（单塔）

COLD 类全交互单塔效果虽好，但每对 (user, item) 都要实时计算，无法离线预存向量，扛不住千级候选。

2024–2025 年出现的 DAT（增强向量）、IntTower（多头 + Sum-Max）、RankTower（门控交叉注意力）尝试在双塔中引入交互，但都有不同缺陷（详见 2.2）。

2.2 现有方案的不足

方案交互位置问题
Two-Tower (DSSM)仅最后点积无早期/晚期交互，效果差
DAT增强向量（隐式早期）参数多、训练慢、增强向量共享（无个性化）
COLD完全早期（单塔）无法离线预存向量，推理延迟高
IntTower晚期（Sum-Max）多头 8x 存储开销，表达力有限
RankTower门控交叉注意力结构复杂、推理慢（33.3ms vs 双塔 25.4ms）
核心空白：在"双塔解耦架构 + 离线 ANN 检索"的前提下，没有方案能同时实现显式早期交互 + 强表达力的晚期交互 + 1x 存储开销 + 推理延迟近双塔。FIT 正是要填补这一空白。

两条关键设计原则：

  1. 解耦性保持：Item Tower 仍是纯 DNN，可离线预计算 item 向量并存入 ANN 索引；User Tower 的 MQM 中物品信息只通过 1 bit 的 Query Index 注入，不破坏解耦。
  2. 受控复杂度：MQM 引入 N×D 维元矩阵（N=64, D=16 → 仅 1024 个参数），LSS 仅 Hu·Hv 维矩阵 + 两层 FC。参数与计算量远低于 RankTower / IntTower。

4. MQM（Meta Query Module）：早期交互

MQM 的目标是在用户塔的底层注入目标物品的语义先验，弥补双塔"晚交互"的信息损失。

4.1 Item Meta Matrix（可学习物品元矩阵）

定义

定义可训练嵌入矩阵：

Q ∈ ℝN × D

其中：

  • N = 64：元向量数量（代表"物品簇"的中心点数量）；
  • D = 16：嵌入维度；
  • 初始化用 Kaiming 均匀分布以获得数值稳定性。

直观理解

可以将 Q 理解为 N 个"伪物品"，每个伪物品代表一类相似物品的"语义中心"。当一个真实物品 e_c 来时，先看看它"最像"哪个伪物品，再把这个伪物品的信息注入用户塔。

为什么不是端到端 Cross-Attention？Cross-Attention 需要实时计算 Q、K、V，对每个 (user, item) 对都要算一遍，无法离线预存。MQM 的"伪物品 + 1 bit 索引"是对 Cross-Attention 的极致蒸馏——只保留"物品属于哪一类"这一离散信息，推理时 1 bit 查表即可。

4.2 无参数自注意力（Parameter-free Self-Attention）

为了让元矩阵 Q 的 N 个伪物品之间有差异性（否则都是相似向量，聚类无意义），论文用了一个无参数的自注意力：

Q* = (Q · QT) · Q

直观解释：

  • 先计算 Q 中所有伪物品的相似度矩阵 Q·QT（形状 N×N）；
  • 用这个相似度矩阵对 Q 重新加权，得到 Q*；
  • 效果：原本相似的伪物品被拉远，原本无关的保持不变，N 个伪物品变得"差异显著"，聚类更有意义。
优势：完全无参数 → 不增加训练负担；又比随机初始化收敛更快（论文消融实验显示 收敛速度 + 最终性能均优于随机初始化）。

4.3 Soft Query（训练） vs Hard Query（推理）

Soft Query（训练用）

对当前候选物品的特征 ec，与所有 N 个元向量计算相似度，用带温度 τ 的 Softmax 加权求和：

k = WK · ec // 投影到与 Q 同一空间
s_i = (k · q*i) / τ // 第 i 个伪物品的相似度
α_i = softmax(s_i) // 权重分布
q̃* = Σi α_i · q*i // Soft Query

效果：多个伪物品同时贡献到用户塔，加速元矩阵学习。训练初期（τ ≈ 1.0）时权重均匀分布，元矩阵的每个位置都能得到梯度更新。

Hard Query（推理用）

仅取相似度最大的那个元向量 q*s，其索引 s ∈ {0,1,...,N-1}：

  • 只需 log2(N) = 6 bit 即可存（N=64）；
  • 论文中更激进，仅用 1 bit slot 索引（这是因为工程实现中按段存储）；
  • 推理时直接查表，零延迟。
训练-推理一致性：Soft Query 和 Hard Query 在训练后期（τ → 0）几乎一致（softmax 趋近于 argmax），保证训练效果在推理时复现。

4.4 温度衰减机制

训练时温度参数 τ 从 1.0 线性衰减到接近 0（如 0.001），衰减周期 = 1 个 epoch 的步数。

作用

阶段τ 范围Softmax 行为作用
训练初期τ ≈ 1.0权重均匀元矩阵各位置都能获得梯度，加速收敛
训练中期τ 递减权重集中逐渐逼近 Hard Query
训练后期τ ≈ 0.001≈ argmax与推理 Hard Query 行为一致，避免训练-推理 gap

消融实验显示，Soft + 温度衰减的训练策略最终 Soft/Hard Query 相似度接近 1.0，证明一致性收敛。

4.5 DIN 交互单元

MQM 的输出（Soft/Hard Query）被作为目标物品信息的代理，输入到用户塔中。论文采用 DIN（Deep Interest Network） 结构处理用户行为序列：

DIN 的加权池化

eui = Σj=1..K a(eui_j, q̃*) · eui_j

其中注意力权重：

a(eui_j, q̃*) = Dice(W · [eui_j ⊕ q̃*] + b)

直观理解：把用户历史行为物品 eui_j 当作 Key，把 Soft/Hard Query 当作 Query，计算每个历史行为与目标物品的"兴趣相关性"，加权求和得到用户当前的兴趣向量。

注意：DIN 在精排中常用，放到召回/预排序中通常有延迟问题。FIT 的巧妙之处在于：DIN 的输入维度是 D=16（极小），且只算一次，计算量与普通序列池化几乎相当。这就是 "全交互 ≠ 推理慢" 的关键证据之一。

5. LSS（Lightweight Similarity Scorer）：晚期交互

LSS 的目标是在两塔输出后，替代传统点积或 Sum-Max，用更轻量的方式做精细打分。

5.1 多头子空间映射

将用户和物品的最终表征映射到 Hu / Hv 个子空间（论文 Hu=Hv=2）：

zuh = Wuh · huL + buh (h = 1, ..., Hu)
zvh = Wvh · hvL + bvh (h = 1, ..., Hv)

每个子空间维度为 64（共 128 维），让相似度在不同子空间中独立计算，捕捉多维度的相关性。

5.2 行列式 FC（结构化全连接）

计算所有用户-物品头对的点积，得到相似度矩阵 S：

S ∈ ℝHu × Hv, Sij = (zui)T · zvj

对 S 做 结构化更新（先按行、再按列，2 层 FC）：

S'i,: = ReLU(W1 · Si,: + b1)
S'':,j = ReLU(W2 · S':,j + b2)

最终打分：

puv = wT · Flatten(S'')

为什么不直接展平 S 接 FC？

直接展平后接 FC 参数量 = Hu·Hv·dhidden，行列式 FC 参数量 = 2·Hv·dhidden + 2·Hu·dhidden，大幅减少参数。消融实验显示行列式 FC 性能优于直接展平 FC。

5.3 理论保证

论文给出了一个重要定理：

「LSS 在 ℓ2 距离下是连续评分函数的通用逼近器（universal approximator），表达能力严格强于传统的 Sum-Max。」

这意味着：

  • 理论上，任何双塔评分函数（只要是连续函数）都可以用 LSS 近似；
  • 实际中，LSS 在 Hu=Hv=2 这种"轻配置"下就已经显著超过 Sum-Max；
  • 增加头数能进一步提升，但存储开销也增加，论文主实验取 2 是为了与双塔保持相同的存储。

6. 训练与推理流程

6.1 损失函数

采用标准的二元交叉熵：

loss = -1/T · Σ(u,v,y) ∈ T [y · log σ(puv) + (1-y) · log(1-σ(puv))]

其中 σ(·) 是 Sigmoid，T 是训练样本对数。简单有效，无特殊设计。

6.2 推理流水线（关键工程实现）

推理时的完全解耦流程是 FIT 工程价值的核心：

离线阶段

  1. 训练完成后，对每个候选物品 v 计算其在 MQM 中的 Hard Query 索引 s ∈ {0,...,N-1}（仅 log2N bit，N=64 → 6 bit，论文工程实现 1 bit slot）。
  2. 把 (item_id, hard_query_index s, item_vector hvL) 一起存入向量数据库。

在线阶段

  1. 从向量库取出 Top-K 候选物品（ANN 检索），得到每个候选的 (hvL, s)。
  2. 在线计算N 套用户表征，每套对应一个可能的 Hard Query：huL(s=0), huL(s=1), ..., huL(s=N-1)。
  3. 对每个候选 (u, v)，根据其 s 索引，从 N 套用户表征中挑选对应的那一套：huL(sv)。
  4. 用 LSS 对 (huL(sv), hvL) 打分。
工程优势：
  • 用户侧 N 套表征可并行计算（一次 forward pass，N 个分支），额外延迟 ≈ 0。
  • Item 侧完全离线，与传统双塔 ANN 检索一样。
  • 不破坏现有 ANN 索引结构（仅多存 1 bit slot）。

9. 工程启示：FIT 给搜一搜的借鉴

9.1 MQM 的"伪物品"思路值得直接借鉴

微信搜一搜有大量"图文 / 视频号 / 公众号 / 小程序"四类候选，每类又有数十种内容标签。可以把"内容标签 / 分类"作为伪物品的语义中心：

  • 离线训练一组 M = 64 个"伪内容标签"向量；
  • 每个真实候选分配 1 个伪标签索引；
  • 用户塔中通过 DIN 加权，让"用户历史在当前候选内容类型下的兴趣"得到强化。

改造成本：仅多 1024 个参数 + 1 bit slot 存储，推理延迟几乎不变。

9.2 LSS 的"多头 + 行列 FC"可以替代现有双塔打分

当前双塔通常用点积或余弦相似度。LSS 仅增加 2 个 H×64 维的 FC 层（H=2），几乎不增加延迟，却能显著提升打分精度。可以先从"图文 i2i 预排序"做试点，对比单点积 vs LSS 的离线 AUC。

9.3 温度衰减的训练 Trick 可直接复用到其他多阶段训练

"训练-推理一致性"是工业模型的常见痛点。FIT 的温度衰减机制（让 Soft 训练 ↔ Hard 推理）是一个通用 Trick：

  • 任何"训练时连续 / 推理时离散"的设计（如向量量化、知识蒸馏中的 soft/hard label）都可以借鉴；
  • 实现简单，仅需一个 τ 的学习率调度；
  • 消融实验显示这是性能的关键保障之一。

9.4 适合作为"从 4 阶段漏斗向 3 阶段融合"的过渡方案

FIT 同时实现早期 + 晚期交互，效果逼近精排单塔；保留双塔的离线 ANN 索引，效率与召回双塔持平。

这意味着：未来可以考虑把 召回 + 预排序合并为单层 FIT，少一层模型 + 少一次 ANN 检索。这是 2026 年召回架构演进的一个可探索方向。

10. 局限与展望

局限性

  • N=64 是个超参，对不同业务可能需要重新调优；过细易过拟合，过粗表达力不足。
  • DIN 交互单元的延迟在长序列场景（>50）会快速放大，论文实验固定 max_len=50。
  • 用户塔要算 N 套表征，理论上比单表征多 N 倍计算（虽然 N=64 在 GPU 上几乎无感，但 CPU 推理仍是负担）。
  • 论文未公开代码，工业复现需要自己做温度调度、Hard Query 索引、并行 N 套表征等工程实现。
  • 论文未提及在线 A/B 数据，仅 4 个公开数据集的离线 AUC，无法评估真实业务增益。

未来方向

  • N 自适应：根据候选物品分布自动决定每个簇的 N 数量（如 SARQ 的"按 path entropy 分配"思路）。
  • DIN 替换为更轻的 Target-Attention（如 SIM、ETA 的 top-k 选择）。
  • 与 LONGER 结合：长序列 + MQM 早期交互 + LSS 晚期打分，做"千级长序列预排序"。
  • 与 OneRec 对比：在相同业务上做"双塔 + FIT" vs "OneRec 生成式"的 A/B，看哪种更适合。
  • 多模态 MQM：把"伪物品"扩展为"伪图文-视频"多模态向量，处理图文/视频混合召回。
