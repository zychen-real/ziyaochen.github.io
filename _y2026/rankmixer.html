1摘要 & 核心贡献

大语言模型(LLMs)的最新进展激发了人们对扩大推荐系统规模的兴趣。然而在工业界实际部署中，仍面临两大核心障碍：

⚠️
严格的延迟/QPS要求
工业推荐系统必须在严格的延迟限制和高 QPS 下进行训练和服务，模型膨胀会带来巨大成本压力。
🐢
CPU 时代遗留架构
现有排序模型中大量人工设计的特征交叉模块继承自 CPU 时代，无法充分利用现代 GPU，导致 MFU 极低（仅 4.5%）。

核心贡献

  • RankMixer：一种硬件感知的模型设计，提供统一且可扩展的特征交互架构。
  • Multi-Head Token Mixing：保留 Transformer 的高并行性，移除二次方复杂度的自注意力。
  • Per-Token FFN：对不同特征子空间独立建模，并维护跨特征空间的交互。
  • Sparse-MoE 变体：将模型扩展至 1B 参数级别；配套ReLU Routing与DTSI策略解决专家不平衡问题。

2研究背景与动机

2.1 推荐系统 Scaling 的现状

自 Kaplan (2020) 和 Hoffmann (2022) 提出 LLM 的 Scaling Laws 以来，研究者一直尝试将"模型规模 → 性能"的规律推广到推荐系统。Ardalani、Chitlangia、Zhang 等人做了初步探索，但工业级应用仍受制于两大瓶颈。

2.2 工业推荐的两大约束

约束 具体表现 影响
延迟 & QPS 工业推荐需在 10~20ms 内返回结果；峰值 QPS 数百万 模型不能无限制膨胀
MFU 极低 历史手工设计模块(DCN, AutoInt, DHEN) 大量使用 element-wise、cross 等操作 GPU 算力浪费严重，扩展成本高昂
异构特征 数百维特征分为数值、ID、交叉、序列等不同类型 自注意力难以学习跨空间相似度

2.3 关键洞察

洞察 1：直接套用 Transformer 中的自注意力并不奏效。推荐特征空间是异构的，在用户 ID 与物品 ID 之间计算相似度内积既困难又昂贵。
洞察 2：从 LLM Scaling Laws 经验看，模型质量主要与总参数相关，不同扩展方向（深度/宽度/Token 数）性能几乎相同；但从计算效率看，扩大隐藏维度比堆叠更多层更有利于 MFU。

3整体架构设计

3.1 设计哲学

RankMixer 是一种硬件感知的模型架构，核心思路是用 GPU 友好的矩阵乘法替代异构、稀疏的交叉模块，实现：

  • 统一的特征交互机制（避免模块碎片化）
  • 算力利用率最大化（MFU 提升 10×）
  • 沿 4 个正交轴灵活扩展：Token 数 T、宽度 D、层数 L、专家数 E

3.3 逐层计算公式

对于第 n 层：

Ŝ_{n-1} = LN( TokenMixing(X_{n-1}) + X_{n-1} )     # 步骤 1：全局 token 混合
X_n     = LN( PFFN(Ŝ_{n-1}) + Ŝ_{n-1} )              # 步骤 2：逐 token 前馈

最终输出：o_output = MeanPool( X_L )

3.4 特征分词（Semantic Token Grouping）

工业推荐模型有 300+ 特征。两种极端方式都有问题：

  • 每个特征 1 个 Token → 参数碎片化，GPU 利用率低
  • 全部 1 个 Token → 退化为 DNN，强势特征淹没弱势特征

RankMixer 的解决方案：利用领域知识将特征按语义分组聚类，拼接后按固定维度切分为 T 个 token。

x_i = Proj( e_input[ d·(i-1) : d·i ] )

3.5 参数 / FLOPs 估算

指标公式说明
Dense 参数量≈ 2·k·L·T·D²k 是 PFFN 扩展因子（通常 4）
Dense FLOPs≈ 4·k·L·T·D²主要是矩阵乘法
缩放维度T, D, L, E四个正交扩展轴

4Multi-Head Token Mixing

4.1 设计动机

Transformer 的自注意力机制在推荐系统上并不奏效。原因有三：

  1. 异构特征空间：用户 ID、物品 ID、统计特征处于完全不同的语义空间，计算内积相似度没有意义
  2. 算力开销巨大：T 个 token 间两两交互，复杂度 O(T²D)
  3. 高频特征主导：自注意力对长尾信号有抑制作用

4.2 实现机制

将每个 token 均匀分为 H 个头，第 h 个头为 x_t^{(h)}，Token Mixing 将同一头位置的向量直接拼接重组：

s^h = Concat( x_1^h, x_2^h, ..., x_T^h )      # 头内拼接

本文设置 H = T，使得残差连接前后 token 数量保持不变。

核心优势

Multi-Head Token Mixing 是完全无参数的操作，仅是张量重排（reshape + transpose），比自注意力更高效，且天然适配异构特征交互。

4.3 与 Self-Attention 的对比

维度Self-AttentionMulti-Head Token Mixing

FLOPs 增量+71.8%≈ 0%
Δ AUC-0.03%基准
异构特征适配差好

5Per-Token FFN (PFFN)

5.1 设计动机

在传统 MMoE/DLRM 结构中，所有专家/FFN 共享输入，但推荐特征天然异构（高频 vs 长尾、稠密 vs 稀疏），需要不同特征子空间独立建模。

5.2 实现机制

每个 token 拥有独立的 FFN 参数：

v_t = f_pffn^{t,2}( GELU( f_pffn^{t,1}( s_t ) ) )    # 公式 3.x

对于第 t 个 token s_t，使用专属的升维-激活-降维网络。

5.3 与 MMoE / Shared FFN 的关键区别

特性MMoEShared FFNPer-Token FFN
输入切分否（共享输入）否是（不同 token）
参数切分是（多专家）否（共享参数）是（按 token 独立）
特征子空间建模弱无强
长尾信号保护一般差好
消融实验结论

将 Per-Token FFN 替换为 Shared FFN，AUC 下降 0.31%。该组件对性能贡献仅次于 Multi-Head Token Mixing。

6Sparse MoE 扩展

6.1 扩展动机

在 Per-Token FFN 基础上引入 MoE 以进一步提升 ROI，但遇到两个经典难题：

  • 专家训练不足：路由不均衡导致部分专家"饿死"，失去价值
  • 路由不平衡：Top-k 路由倾向于激活少数专家

6.2 ReLU Routing（替代 Top-k + Softmax）

使用 ReLU 门控 + 自适应 ℓ₁ 惩罚：

gate = ReLU( W_gate · s_t )                         # 非负门控
L_reg = α · ||gate||_1                               # 稀疏正则

高信息量的 token 可激活更多专家，稀疏性由正则项约束。

6.3 DTSI-MoE (Dense-Training / Sparse-Inference)

关键创新：训练时使用两个路由器（h_train 和 h_infer），推理时仅使用 h_infer。

  • L_reg 仅作用于 h_infer
  • 两个路由器在训练时均更新
  • 保证所有专家在训练时获得充分梯度，防止"专家饥饿/死亡"
关键效果

结合 DTSI + ReLU 路由的 SMoE，在稀疏激活率降至 1/8 时，仍能几乎保留 1B Dense 模型的全部精度，并带来 +50% 吞吐量提升。

6.4 Scaling 维度

参数和算力可沿 4 个正交轴扩展：

🧩
Token 数 T
更多特征分片，捕获更细粒度子空间
📏
宽度 D
每个 token 维度，利于提高 MFU
🏗️

增加网络深度，捕获高阶交互

前三节从公式层面描述了 RankMixer 的设计，但纯数学描述对工程同学来说不够直观。本节用一个极简 toy 例子（T=2, D=4, L=1, B=1）把整个前向过程手算一遍，每一步都给出张量形状与具体数值。理解了这个例子，工业级（D=1536, T=32, L=2）模型的推理过程就完全相同。

RankMixer 关键超参：T=2 个 token，D=4 维，L=1 层，batch size = 1。PFFN 扩展因子 k=2。

7.1 Step 1 — 特征嵌入 & 语义分词

每个特征先经过各自的 Embedding / 归一化：

原始 embedding（举例值）： e_user_id = [0.12, 0.45, 0.78, 0.33, ...] // 64 维 e_item_id = [0.67, 0.21, 0.89, 0.12, ...] // 64 维 e_age = [0.50, 0.50, 0.50, 0.50] e_time_of_day = [0.10, 0.30, 0.20, 0.90]

语义分组（利用领域知识）：

group_id = Concat(e_user_id, e_item_id) // 128 维 group_stat = Concat(e_age, e_time_of_day) // 8 维

按固定维度 d=D=4 切分，组内做平均聚合：

token_1 = Proj(group_id[0:64]) = [ 0.41, 0.23, 0.55, 0.18 ] // ID 子空间 token_2 = Proj(group_stat[0:4]) = [ 0.30, 0.40, 0.35, 0.70 ] // 统计子空间

组成输入张量 X₀：

X₀ shape = [B=1, T=2, D=4] X₀ = ┌ ┐ │ 0.41 0.23 0.55 0.18 │ // token_1: ID 类聚合 │ 0.30 0.40 0.35 0.70 │ // token_2: 统计类聚合 └ ┘

7.2 Step 2 — LayerNorm(X₀)

LN_X₀ = ┌ ┐ │ -0.52 -1.10 0.39 -0.95 │ │ -1.05 -0.40 0.18 0.95 │ └ ┘

7.3 Step 3 — Multi-Head Token Mixing 核心

完全无参数的张量重排，替代二次方 Self-Attention。设 H = T = 2，每头 D/H = 2 维：

head = 0

┌ ┐ │ -0.52 -1.10 │ // t1 head0 │ -1.05 -0.40 │ // t2 head0 └ ┘

head = 1

┌ ┐ │ 0.39 -0.95 │ // t1 head1 │ 0.18 0.95 │ // t2 head1 └ ┘

把"同一 head、不同 token"的向量拼成新 token — 0 个可学习参数：

S̃ = ┌ ┐ │ -0.52 -1.10 0.39 -0.95 │ // 新 token_1 = t1_h0 ⊕ t2_h0 │ 0.39 -0.95 -0.52 -1.10 │ // 新 token_2 = t1_h1 ⊕ t2_h1 └ ┘
直觉理解

每个新 token 现在混合了所有原 token 在同一子空间的信息。但 0 个可学习参数，仅是 reshape + transpose + reshape 三个张量操作。

7.4 Step 4 — 残差 + LayerNorm

Ŝ = S̃ + X₀ Ŝ = ┌ ┐ │ -0.11 -0.87 0.94 -0.77 │ │ 0.59 0.70 0.63 0.95 │ └ ┘ LN_Ŝ = LayerNorm(Ŝ) shape = [1, 2, 4] LN_Ŝ = ┌ ┐ │ -0.40 -1.00 0.80 -0.90 │ │ 0.20 0.40 0.25 0.95 │ └ ┘

7.5 Step 5 — Per-Token FFN 关键

每个 token 使用独立的 FFN 参数（与 Transformer 的"所有 token 共享一个 FFN"完全相反）。

扩展维度：d_ff = k·D = 2·4 = 8

token_1 专属 FFN 独立参数 W1_t1, W2_t1

h₁ = GELU(W1_t1 · LN_Ŝ[token_1])   // 4 → 8
v₁ = W2_t1 · h₁                     // 8 → 4

v₁ = [ 0.30,  0.55, -0.20,  0.78 ]

↑ ID 子空间专精的 FFN，独立学到了 ID 类特征的交互模式

token_2 专属 FFN 独立参数 W1_t2, W2_t2

h₂ = GELU(W1_t2 · LN_Ŝ[token_2])   // 4 → 8
v₂ = W2_t2 · h₂                     // 8 → 4

v₂ = [-0.40,  0.12,  0.66, -0.35 ]

↑ 统计子空间专精的 FFN，避免被高频 ID 特征"霸占"容量

V = PFFN(LN_Ŝ) shape = [1, 2, 4] V = ┌ ┐ │ 0.30 0.55 -0.20 0.78 │ // v1 (ID 子空间) │ -0.40 0.12 0.66 -0.35 │ // v2 (统计子空间) └ ┘

7.6 Step 6 — 残差 → 输出 X₁

X₁ = V + Ŝ X₁ = ┌ ┐ │ 0.19 -0.32 0.74 0.01 │ │ 0.19 0.82 1.29 0.60 │ └ ┘

如果 L=2，X₁ 会作为下一层的输入再次进入同一个 Block。

7.7 Step 7 — Mean Pooling → 多任务预测

o = MeanPool(X₁) shape = [1, 4] o = [ 0.19, 0.25, 1.01, 0.31 ] logit_finish = W_finish · o + b_finish = 0.86 → Sigmoid → 0.703 (完播概率) logit_skip = W_skip · o + b_skip = -0.34 → Sigmoid → 0.416 (划走概率) logit_like = W_like · o + b_like = 0.12 → Sigmoid → 0.530 (点赞概率) logit_follow = W_follow · o + b_follow = 0.42 → Sigmoid → 0.603 (关注概率)

7.8 Sparse MoE 变体示例

把 PFFN 升级为 MoE（E=4 个专家，top-2 激活 + ReLU 路由）：

def moe_ffn(s_t, experts, W_gate):
    # 1) ReLU 门控（非负，天然稀疏）
    gate = ReLU(W_gate @ s_t)               # shape [E=4]
    #    → [0.00, 0.45, 0.82, 0.13]

    # 2) 选 top-2 专家
    top_idx = topk(gate, k=2)                # [2, 3]

    # 3) 加权融合
    y = (gate[2] * experts[2](s_t) + gate[3] * experts[3](s_t)) / (gate[2] + gate[3])

    # 4) 稀疏正则（仅作用于 h_infer）
    L_reg = α * norm(gate, p=1)

    return y, L_reg

DTSI 双路由器：

训练时：L_total = L_task + α · ||gate_infer||₁ # h_infer 计算正则 ├─ h_train 路由器：只用于梯度回传，确保所有专家都"见过"足够样本 └─ h_infer 路由器：承担实际激活分布，推理时单独使用 推理时：仅用 h_infer → 在训练时强制保证 h_infer 学到的专家是"充分训练过"的

7.9 完整数据流图

X₀ [1, 2, 4] ← 输入 token │ ├─ LayerNorm // [1, 2, 4] │ ├─ Token Mixing (无参数) // [1, 2, 4] ← 跨 token 信息聚合 │ ├─ 残差 + LayerNorm // [1, 2, 4] │ ├─ PFFN (T=2 个独立 FFN) // [1, 2, 4] ← 子空间专精 │ ├─ 残差 → X₁ [1, 2, 4] │ └─ × L 层 │ ▼ MeanPool → o [1, 4] → 多任务塔 (Finish / Skip / Like / Follow)

7.10 关键 takeaway

步骤作用参数量FLOPs
Token Mixing 跨 token 信息聚合，替代 Self-Attention 0（无参数） ≈ 0（仅 reshape）
PFFN 每个 token 独立学习 T · (2·D·d_ff) ≈ T·4D²·k T · (4·D·d_ff) ≈ T·8D²·k
MoE 升级 进一步提升 ROI + (E-1) 组专家 仅激活 top-k
Self-Attention（对比） 相似度内积 4·D² 2·T·D² （O(T²D)）
本例中的算力账

① Token Mixing 完全免费（0 参数、0 FLOPs），却实现了全局信息交换；
② PFFN 贡献了主要参数和算力，但全是 GPU 友好的大矩阵乘；
③ 相比 Self-Attention，省掉 71.8% FLOPs；
④ 这就是 MFU 从 4.5% → 45% 的根本原因——没有 element-wise、没有 sparse gather，全是 cublas 矩阵乘。

8实验结果

11.1 实验环境

  • 数据：抖音推荐系统在线日志，每日万亿级记录，实验取两周数据。300+ 特征（数值、ID、交叉、序列），数十亿用户 ID、数亿视频 ID
  • 硬件：数百 GPU，混合分布式训练框架（稀疏部分异步更新，稠密部分同步更新）
  • 优化器：稠密部分 RMSProp (lr=0.01)，稀疏部分 Adagrad

11.2 评估指标

  • 性能：AUC, UAUC（Finish / Skip 标签）。工业界 AUC 提升 0.0001 即显著
  • 效率：Dense-Param, Training FLOPs/Batch, MFU

11.4 关键发现

  1. 简单把 DLRM 放大到 100M 收益极小（仅 +0.15%），证明针对推荐数据特性设计架构是必要的
  2. DCN/RDCN/AutoInt/DHEN 等模型即使参数小，FLOPs 也很大，架构存在效率短板
  3. RankMixer 在取得最佳性能的同时，FLOPs 相对适中，实现容量与计算负载的最佳平衡
  4. 从 100M 扩展到 1B，AUC 仍有显著提升（+0.31%），验证 Scaling Law 持续生效

9Scaling Laws 研究

11.1 核心结论

RankMixer 展现出最陡峭的 Scaling Law 曲线（无论参数维度还是 FLOPs 维度）。在工业级数据上验证了 LLM Scaling Laws 经验在推荐系统中的适用性。

11.3 扩展维度选择

关键发现：与 LLM 一致，模型质量主要与总参数量相关，不同扩展方向（深度 L、宽度 D、Token 数 T）性能几乎相同。

但从计算效率看，增大隐藏维度比堆叠更多层能产生更大的矩阵乘形状，从而获得更高的 MFU。

11.3 Sparse MoE 扩展性 & 专家平衡

  • 扩展性：Vanilla SMoE 性能随专家激活减少单调下降；DTSI + ReLU 路由的 SMoE 在稀疏率 1/8 时仍能保留 1B Dense 模型几乎全部精度，吞吐量 +50%
  • 专家平衡：DTSI 保证训练时专家获得充分梯度；ReLU 路由使不同 token 的激活比例动态适应其信息含量。Figure 4 显示不同 token 激活比例呈现健康差异（而非坍缩到少数专家）

11线上部署与 A/B 测试

11.1 推理成本：参数 70× 增长但延迟不变

从原基线 16M 参数扩展到 RankMixer-1B（参数量增加 70×），推理延迟从 14.5ms 降至 14.3ms。原因：

  1. FLOPs/Param 比率下降 3.6×：RankMixer 设计使参数 +70× 时 FLOPs 仅 +约 20×
  2. MFU 提升 10×：从 4.47% 升至 44.57%，从 Memory-bound 转为 Compute-bound
  3. FP16 量化：理论硬件峰值算力 +2×

12总结与启示

11.1 核心创新点

🎯
硬件感知架构设计
抛弃 CPU 时代交叉模块，用 GPU 友好的矩阵乘和 token 重排实现 10× MFU 提升
🧠
取代 Self-Attention
Multi-Head Token Mixing 无参数、更高效，天然适配异构特征
⚖️
Per-Token FFN
为每个 token 分配独立 FFN，避免高频特征淹没长尾信号
🚀
DTSI + ReLU 路由
解决 MoE 专家饥饿和路由不平衡问题，实现 1B 参数规模

11.2 工业价值

  • ✓ 证明工业级推荐系统也可遵循 Scaling Laws，模型质量与参数量正相关
  • ✓ 实现"参数 100× 但延迟不变"的工程奇迹
  • ✓ 全流量上线 1B 模型，未增加服务成本
  • ✓ 在推荐和广告两大场景同时验证通用性

11.3 对搜广推同行的启示

启示 1：不要简单堆叠 Transformer，要为推荐数据特性设计专用架构（如 Multi-Head Token Mixing 替代 Self-Attention）。
启示 2：从 LLM Scaling Laws 借鉴经验，但要注意工业部署的延迟/QPS 约束，MFU 提升带来的成本节约与模型规模同等重要。
启示 3：MoE 扩展必须配套解决专家饥饿问题，DTSI 训练-推理分离是一种有效方案。
启示 4：低活跃/长尾用户是大模型最受益的群体，规模化扩展有显著业务价值。

11.4 局限性 & 未来方向

  • 目前仅在抖音场景验证，跨平台泛化性需进一步研究
  • 稀疏激活 SMoE 已能保留 1B 精度，但专家合并 / 蒸馏仍有空间
  • Multi-Head Token Mixing 的理论基础（与 MLP-Mixer 的关系）值得深入
